# Установка и развёртывание

Есть два способа поставить робота.

| | Часть 1. На своём компьютере | Часть 2. На сервере |
|---|---|---|
| **Для чего** | попробовать, настроить шаблоны, проверить на тестовых сделках | постоянная работа с клиентами |
| **Что нужно** | компьютер с Docker Desktop | сервер (VPS) и домен |
| **Время** | 10–15 минут | 30–40 минут |
| **Когда робот работает** | пока компьютер включён и не спит | круглосуточно |
| **Как узнаёт о событиях** | сам проверяет: новые сделки — раз в минуту, ответы клиентов — раз в 5 минут | мгновенно, через вебхуки |

Начните с первой части: всё, что вы настроите на компьютере (подключения, шаблоны, пользователи),
потом можно перенести на сервер одним файлом ([как перенести](#перенос-с-компьютера-на-сервер)).

После установки остаётся подключить Битрикс и Орбиту в панели — это **[docs/НАСТРОЙКА.md](docs/НАСТРОЙКА.md)**.

# Часть 1. На своём компьютере

## 1. Что понадобится

| Что | Зачем |
|---|---|
| **[Docker Desktop](https://www.docker.com/products/docker-desktop/)** для macOS или Windows | в нём запускается робот |
| **Битрикс24** с правами администратора | создать вебхук |
| **Аккаунт Орбиты** с подключённым WhatsApp, Max или Telegram | через него уходят сообщения |

Установите Docker Desktop и запустите его: в строке меню (macOS) или в трее (Windows) должен появиться
значок кита. Все команды ниже вводятся в Терминале (macOS) или PowerShell (Windows).

## 2. Скачать робота

```bash
git clone https://github.com/zznelor/contact_robot.git first-contact
cd first-contact
```

Если git не установлен — скачайте архив (https://github.com/zznelor/contact_robot/archive/refs/heads/main.zip — или на странице репозитория кнопка «Code» → «Download ZIP»), распакуйте и перейдите
в папку в Терминале: `cd ` и перетащите папку в окно Терминала.

## 3. Запустить

```bash
cp .env.example .env
docker compose up -d app
```

В Windows (PowerShell) вместо `cp` — `copy .env.example .env`.

Файл `.env` на компьютере заполнять не нужно: домен нужен только на сервере. Первый запуск занимает
1–3 минуты — Docker скачивает и собирает образ.

Проверить, что робот работает:

```bash
curl -s http://127.0.0.1:8080/health    # {"ok":true,"enabled":false}
```

## 4. Первый вход

Узнайте одноразовый код:

```bash
docker compose exec app python -m first_contact setup-code
```

Откройте в браузере **<http://127.0.0.1:8080>**. На странице «Первый запуск» введите код, свою почту и пароль
(не короче 8 символов) — это учётная запись администратора.

## 5. Настроить

Пройдите **[docs/НАСТРОЙКА.md](docs/НАСТРОЙКА.md)**, но **пропустите шаги 2 и 4** (вебхуки Битрикса
и Орбиты): Битрикс и Орбита не могут достучаться до вашего компьютера из интернета. Без вебхуков робот
сам проверяет новые сделки раз в минуту, а ответы клиентов — раз в 5 минут (если включён ответ по
шаблону). Для проверки этого достаточно.

Не заполняйте на компьютере «секрет вебхука» Орбиты: если он задан, робот перестаёт сам проверять
ответы клиентов и ждёт их от Орбиты — а она на компьютер их не пришлёт.

Робот ничего не отправляет, пока вы его явно не включите. Для первых проверок создайте в Битриксе
тестовую сделку со своим номером телефона.

## 6. Что учесть

- **Робот работает, только пока компьютер включён и не спит.** Сделки, пришедшие, пока компьютер был
  выключен, робот обработает после включения, если с их создания прошло меньше 48 часов. Сообщения
  уходят только в рабочее время.
- **Подтверждение отправки.** Иногда Орбита отвечает «передано, ждём подтверждения», а подтверждение
  присылает только вебхуком. На компьютере вебхук не дойдёт, и через 30 минут сделка получит статус
  «проверить». Откройте переписку в Орбите: если сообщение не ушло — нажмите в панели «Повторить»,
  если ушло — не нажимайте, иначе клиент получит его дважды. На сервере с вебхуками такого не бывает.
- **В базе на компьютере — телефоны и имена клиентов и ключи Битрикса и Орбиты.** Не оставляйте робота
  на общем компьютере. Для постоянной работы с клиентами переходите на сервер (часть 2).

## Команды на компьютере

| Команда | Что делает |
|---|---|
| `docker compose logs -f app` | журнал робота в реальном времени (Ctrl+C — выйти) |
| `docker compose exec app python -m first_contact check` | проверить связь с Битриксом и Орбитой |
| `docker compose stop app` | остановить робота (данные сохранятся) |
| `docker compose up -d app` | запустить снова |
| `docker compose down -v` | **удалить робота вместе с базой** — настройки, пользователи и сделки пропадут |

Остальные команды (резервная копия, сброс пароля) — те же, что на сервере, см. [Обслуживание](#обслуживание).

## Без Docker

Нужен Python 3.11+ и [uv](https://docs.astral.sh/uv/). В папке проекта:

```bash
uv sync
uv run python -m first_contact run
```

Код первого входа появится в выводе команды (или `uv run python -m first_contact setup-code`
в другом окне Терминала). Панель — <http://127.0.0.1:8080>, база — `data/state.sqlite3`.
Остальные команды — те же, только вместо `docker compose exec app python` пишите `uv run python`.

# Часть 2. На сервере

Почему для постоянной работы нужен сервер, а не компьютер в офисе: Битрикс и Орбита присылают роботу
события через интернет, поэтому у робота должен быть постоянный публичный адрес. Сервер работает
круглосуточно.

Нужны базовые навыки: подключиться к серверу по SSH и вставить команды. Займёт 30–40 минут, большая
часть — ожидание сервера и DNS.

## 1. Что понадобится

| Что | Зачем | Пример |
|---|---|---|
| **Сервер (VPS)** с Linux: 1 ядро, 1 ГБ памяти, 10 ГБ диска | на нём работает робот | Ubuntu 24.04 у любого хостинга |
| **Домен или поддомен** | адрес панели и вебхуков; без него не будет HTTPS | `robot.company.ru` |
| **Битрикс24** с правами администратора | создать вебхуки | — |
| **Аккаунт Орбиты** с подключённым WhatsApp, Max или Telegram | через него уходят сообщения | — |

Где хранить: на сервере будут телефоны и имена клиентов. Если вы работаете с клиентами из России,
по закону о персональных данных (152-ФЗ) сервер лучше взять у российского хостинга.

## 2. Сервер

1. Закажите VPS с **Ubuntu 22.04 или 24.04** — подойдёт самый дешёвый тариф.
2. Запишите **IP-адрес** сервера и пароль (или SSH-ключ) от пользователя `root`.
3. Если у хостинга есть файрвол в панели управления, откройте входящие порты **22, 80, 443**.

Подключитесь к серверу:

```bash
ssh root@IP-АДРЕС-СЕРВЕРА
```

Все команды ниже выполняются на сервере.

## 3. Домен

В панели управления доменом (там, где вы его покупали) создайте запись:

| Тип | Имя | Значение |
|---|---|---|
| `A` | `robot` (или любое) | IP-адрес сервера |

Получится `robot.company.ru`. Запись начинает работать через 5–30 минут. Проверить:

```bash
ping -c 1 robot.company.ru      # должен показать IP вашего сервера
```

## 4. Docker

```bash
curl -fsSL https://get.docker.com | sh
docker compose version          # должна показаться версия, например v2.29
```

## 5. Скачать робота

```bash
apt-get install -y git
git clone https://github.com/zznelor/contact_robot.git /opt/first-contact
cd /opt/first-contact
```

Если git недоступен — скачайте архив репозитория (https://github.com/zznelor/contact_robot/archive/refs/heads/main.zip), распакуйте в
`/opt/first-contact`.

## 6. Настроить домен

```bash
cp .env.example .env
nano .env
```

Впишите свой домен и сохраните (Ctrl+O, Enter, Ctrl+X):

```
DOMAIN=robot.company.ru
```

Больше в файле ничего менять не нужно: всё остальное настраивается в панели в браузере.

## 7. Запустить

```bash
docker compose up -d
```

Первый запуск занимает 1–3 минуты: собирается образ, Caddy получает HTTPS-сертификат.

Проверить, что всё работает:

```bash
docker compose ps                         # app и caddy — в состоянии running / healthy
curl -s https://robot.company.ru/health   # {"ok":true,"enabled":false}
```

## 8. Первый вход

Узнайте одноразовый код:

```bash
docker compose logs app | grep "Код первого входа"
```

Откройте в браузере `https://robot.company.ru`. Откроется страница «Первый запуск»: введите код, свою почту
и пароль (не короче 8 символов). Это учётная запись администратора.

Код действует, пока не создан первый администратор. Если строки в логе не видно (лог мог прокрутиться):

```bash
docker compose exec app python -m first_contact setup-code
```

Дальше — настройка в панели: **[docs/НАСТРОЙКА.md](docs/НАСТРОЙКА.md)**, все шаги, включая вебхуки.
Робот ничего не отправляет, пока вы его явно не включите.

Если вы уже настроили робота на компьютере — не проходите настройку заново, а перенесите базу (ниже).

## Перенос с компьютера на сервер

Всё, что настроено на компьютере (подключения, шаблоны, пользователи, история сделок), переезжает
одним файлом базы.

1. **На компьютере** — выключите робота в панели («Настройки» → «Выключить робота»), чтобы клиентам
   не писали два робота сразу, и сделайте копию базы:

   ```bash
   docker compose exec app python -m first_contact backup
   docker compose cp app:/data/backup-$(date +%F).sqlite3 ./backup-$(date +%F).sqlite3
   ```

   В папке проекта появится файл `backup-ГГГГ-ММ-ДД.sqlite3`. В Windows (PowerShell) `$(date +%F)` не
   сработает — впишите дату из ответа первой команды, например `backup-2026-10-20.sqlite3`.

2. **Скопируйте файл на сервер** (команда на компьютере, подставьте дату и IP):

   ```bash
   scp backup-2026-10-20.sqlite3 root@IP-АДРЕС-СЕРВЕРА:/opt/first-contact/
   ```

3. **На сервере** — после шагов 1–7 части 2 восстановите базу:

   ```bash
   cd /opt/first-contact
   docker compose cp ./backup-2026-10-20.sqlite3 app:/data/restore.sqlite3
   docker compose exec app python -m first_contact restore /data/restore.sqlite3
   docker compose restart app
   ```

4. Откройте `https://robot.company.ru` и войдите с той же почтой и паролем, что на компьютере.
   Донастройте то, чего на компьютере не было: **вебхуки Битрикса и Орбиты** (шаги 2 и 4 в
   [docs/НАСТРОЙКА.md](docs/НАСТРОЙКА.md)). Проверьте «Проверку связи» и включите робота.

5. На компьютере робота можно удалить: `docker compose down -v`. Файл копии удалите или уберите
   в надёжное место — в нём ключи Битрикса и Орбиты.

## Обслуживание

Команды выполняются в папке проекта — на сервере это `/opt/first-contact`.

### Обновление

```bash
cd /opt/first-contact
docker compose exec app python -m first_contact backup   # на всякий случай
git pull
docker compose up -d --build
```

Настройки, шаблоны, пользователи и история сделок хранятся в базе в томе `data` и при обновлении
не теряются. Если схема базы поменялась, она обновится сама при запуске.

Если вы дорабатывали код под себя, держите доработки в своей ветке (`git checkout -b моя-версия`),
а обновления забирайте `git pull` с последующим слиянием.

### Резервная копия

```bash
cd /opt/first-contact
docker compose exec app python -m first_contact backup
docker compose cp app:/data/backup-$(date +%F).sqlite3 ./backup-$(date +%F).sqlite3
```

Файл `backup-ГГГГ-ММ-ДД.sqlite3` — вся база: настройки (включая ключи Битрикса и Орбиты), пользователи,
сделки. Храните его в надёжном месте, у него те же права доступа, что у ключей.

Автоматически каждую ночь — добавьте в `crontab -e`:

```
0 3 * * * cd /opt/first-contact && docker compose exec -T app python -m first_contact backup
```

### Восстановление из копии

```bash
cd /opt/first-contact
docker compose cp ./backup-2026-10-20.sqlite3 app:/data/restore.sqlite3
docker compose exec app python -m first_contact restore /data/restore.sqlite3
docker compose restart app
```

### Забыли пароль

Администратор может выдать новое приглашение («Настройки» → «Команда» → «Пригласить»). Если пароль забыл
единственный администратор:

```bash
docker compose exec app python -m first_contact reset-password почта@company.ru
```

Создать ещё одного администратора из командной строки:

```bash
docker compose exec app python -m first_contact create-admin почта@company.ru
```

### Полезные команды

| Команда | Что делает |
|---|---|
| `docker compose logs -f app` | журнал робота в реальном времени (Ctrl+C — выйти) |
| `docker compose exec app python -m first_contact check` | проверить связь с Битриксом и Орбитой |
| `docker compose restart app` | перезапустить робота |
| `docker compose down` | остановить всё (данные сохранятся) |
| `docker compose up -d` | запустить снова |

Временно остановить отправку, не трогая сервер: в панели «Настройки» → «Выключить робота».

## Если что-то не работает

**На компьютере**

| Признак | Что проверить |
|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен — откройте его и подождите, пока значок кита перестанет мигать |
| `port is already allocated` / `address already in use` | порт 8080 занят другой программой. Остановите её или в `docker-compose.yml` замените `"127.0.0.1:8080:8080"` на `"127.0.0.1:8090:8080"` и откройте <http://127.0.0.1:8090> |
| Сделки появляются с задержкой до минуты, ответы клиентов — до 5 минут | так и должно быть на компьютере: без вебхуков робот проверяет сам |
| Сделка в статусе «проверить», в журнале «нет подтверждения отправки» | на компьютере это ожидаемо (часть 1, шаг 6) — проверьте переписку в Орбите |
| Робот не замечает ответы клиентов | в панели заполнен секрет вебхука Орбиты — на компьютере его нужно оставить пустым (часть 1, шаг 5) |

**На сервере**

| Признак | Что проверить |
|---|---|
| Браузер не открывает `https://robot.company.ru` | `ping robot.company.ru` показывает IP сервера? Открыты ли порты 80 и 443 в файрволе хостинга? `docker compose logs caddy` — есть ли ошибки получения сертификата |
| Caddy пишет `no such host` или `DNS problem` | DNS-запись ещё не обновилась — подождите 30 минут и выполните `docker compose restart caddy` |
| Caddy не стартует, `DOMAIN` пустой | в `.env` нет строки `DOMAIN=…` |
| `docker compose ps` показывает app `unhealthy` или `restarting` | `docker compose logs app` — последняя ошибка внизу |
| Нет строки «Код первого входа» | `docker compose exec app python -m first_contact setup-code` |
| «Форма отправлена не со страницы панели» | открывайте панель по тому же адресу, что в `DOMAIN`, а не по IP |
| Робот не пишет клиентам | Панель → «Проверка связи»: все строки зелёные? Робот включён? Сейчас внутри окна отправки? |
| Сделки появляются с задержкой до минуты | не настроен исходящий вебхук Битрикса — это нормально, но можно ускорить (docs/НАСТРОЙКА.md, шаг 2) |

## Без Docker на сервере

Можно, если у вас уже есть свой веб-сервер (nginx и т. п.):

1. Python 3.11+, `uv sync` в папке проекта.
2. Запуск как служба systemd: `uv run python -m first_contact run 8080` (переменная `DB_PATH` — где база).
   Сервис слушает только `127.0.0.1` — так и нужно, если веб-сервер на той же машине.
3. Проксирование `https://ваш-домен` → `http://127.0.0.1:8080` с заголовками `X-Forwarded-Proto` и
   `X-Forwarded-For`, переменная `PUBLIC_URL=https://ваш-домен`. Если веб-сервер на другой машине, задайте
   `HOST=0.0.0.0` и `FORWARDED_ALLOW_IPS=<его IP>` и закройте порт 8080 для всех остальных.

## Безопасность

- Порт 8080 открыт только для самого компьютера или сервера; на сервере снаружи панель доступна только
  через HTTPS (Caddy). При запуске без Docker робот слушает только `127.0.0.1`: из локальной сети
  (например, в общем Wi-Fi) панель не видна.
- Почта пользователя проверяется при создании: адреса с кавычками, пробелами и скобками не принимаются.
- В базе лежат ключи Битрикса и Орбиты. Не давайте доступ к серверу, компьютеру с роботом и копиям базы
  посторонним.
- Пароли пользователей хранятся в виде хэша (scrypt), сессии — 30 дней.
- После 10 неверных паролей вход с этого адреса блокируется на 15 минут.
- Ключ Орбиты выпускайте только с тремя нужными правами (см. docs/НАСТРОЙКА.md) — не со всеми подряд.
