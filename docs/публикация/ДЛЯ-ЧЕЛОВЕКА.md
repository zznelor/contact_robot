# Как выложить проект на GitHub или GitLab и не раскрыть секреты

Версия от 25.10.2026. Инструкция для агента — [ДЛЯ-CLAUDE.md](ДЛЯ-CLAUDE.md).

## Коротко

Если идти по шагам 1–5, в общий доступ уйдёт только код, а ключи, базы и рабочие заметки останутся у вас. Документ рассчитан на проекты вроде робота первого контакта: небольшой сервис, который связывает Битрикс24, Орбиту и мессенджеры, а код пишет и выкладывает Claude.

**Главное правило: всё, что попало в git, опубликовано навсегда.** Если удалить файл следующим коммитом, он всё равно останется в истории. Ключ, который хоть минуту пролежал в публичном репозитории, нужно перевыпустить.

Команды для терминала даны для macOS. Готовые промпты для Claude собраны в конце документа, в разделе «Готовые промпты».

## Что нельзя публиковать

В публичный репозиторий не должен попасть ни один пункт из таблицы.

| Что | Примеры | Чем опасно |
| --- | --- | --- |
| Ключи и токены | файл `.env`, вебхук Битрикса `…bitrix24.ru/rest/1/<токен>/`, ключ Орбиты `orb_pk_…`, токены Яндекса, ботов, GitHub | Кто угодно сможет читать сделки и писать клиентам от имени компании |
| Закрытые ключи | `id_ed25519`, `*.pem`, `*.key`, `credentials.json` | Доступ к серверам и репозиториям |
| Базы и выгрузки | `*.sqlite3`, папка `data/`, резервные копии, `.csv` и `.xlsx` из CRM | Персональные данные клиентов, сохранённые в панели ключи |
| Логи | `*.log`, папка `logs/` | В них оседают адреса с токенами, телефоны, тексты сообщений |
| Реальные данные в тестах и инструкциях | живые телефоны, адрес тестового портала, номера сделок и диалогов, имена заказчиков | Те же персональные данные, только спрятанные в коде |
| Рабочие заметки | журнал, план, ТЗ, переписка, цены и условия договора | Коммерческая тайна и чужие имена |
| Скриншоты и видео | записи экрана панели, CRM, кабинета Орбиты | В кадр попадают ключи и почты. Программы это не ловят, проверять глазами |
| Служебные папки | `.venv/`, `node_modules/`, кэши, `.DS_Store`, настройки редактора | Личные пути и имя пользователя на компьютере |
| Почта автора коммитов | `имя@gmail.com` в каждом коммите | Уходит публично, её собирают спам-боты |

**Публиковать можно:** код, инструкции, лицензию, файл `.env.example` с пустыми значениями, тесты с выдуманными данными: `+7 999 000-00-01`, `ваш-портал.bitrix24.ru`, `orb_pk_secret123456`.

## Шаг 1. Подготовить проект

Репозиторий — это отдельная папка только с тем, что можно показать. Всё остальное лежит уровнем выше, и тогда случайно закоммитить его нельзя.

```
мой-проект/                ← рабочая папка, НЕ репозиторий
├── .env                   ← настоящие ключи для тестов
├── ЖУРНАЛ.md, ПЛАН.md     ← заметки
├── ВИДЕО-ДЕМО/            ← записи экрана
└── first-contact/         ← репозиторий
    ├── .gitignore
    ├── .dockerignore
    ├── .env.example       ← имена настроек, значения пустые
    ├── src/ tests/ docs/
    └── data/              ← база, в git не попадает
```

Что сделать:

1. Перенести ключи, заметки и видео из папки репозитория уровнем выше.
2. Положить в репозиторий `.gitignore` — список файлов, которые git не берёт. Тот же список — в `.dockerignore`, иначе ключи попадут в Docker-образ. Проще попросить Claude (промпт 1 в конце). Минимальный состав:

```
.env
.env.*
!.env.example
*.pem
*.key
credentials*.json
data/
*.sqlite3
*.db
backup-*
*.log
*.csv
*.xlsx
*.mov
*.mp4
.venv/
__pycache__/
.pytest_cache/
node_modules/
.DS_Store
.idea/
.vscode/
```

3. Сделать `.env.example`: те же строки, что в `.env`, но без значений и с комментариями. По нему тот, кто ставит сервис, поймёт, что заполнить.
4. Убедиться, что в коде нет ни одного настоящего ключа. Ключи берутся только из `.env` или из настроек, которые владелец вводит в панели.
5. Убедиться, что сервис не пишет ключи в логи, а в панели показывает их маской: `orb_pk_…3f9a`.

Проверка в терминале, из папки репозитория:

```
git check-ignore -v .env data
git ls-files | grep -Ei 'env|sqlite|data/|key|token|log'
```

Первая команда должна показать правило для каждого файла. Вторая должна вывести только `.env.example` или ничего.

## Шаг 2. Настроить репозиторий

Эти настройки делаете вы сами в браузере, один раз на репозиторий. Они защищают даже тогда, когда агент ошибётся: сервер просто не примет опасное действие.

**2.1. Создать репозиторий закрытым.** Публичным он станет только на шаге 5, после проверки.

- GitHub: «+» в правом верхнем углу → New repository → Private.
- GitLab: New project → Create blank project → Visibility Level: Private.

**2.2. Скрыть свою почту в коммитах.**

- GitHub: аватар → Settings → Emails → включить «Keep my email addresses private» и «Block command line pushes that expose my email». Скопировать адрес вида `12345+логин@users.noreply.github.com`.
- GitLab: аватар → Edit profile → Commit email → Use a private email.
- В терминале, в папке репозитория: `git config user.email "<скопированный адрес>"`.

**2.3. Защитить главную ветку `main`.** В неё нельзя будет писать напрямую и нельзя переписать историю, только через запрос на слияние, который принимаете вы.

- GitHub: репозиторий → Settings → Rules → Rulesets → New branch ruleset. Target branches: Include default branch. Включить Restrict deletions, Require a pull request before merging, Block force pushes. Enforcement status: Active.
- GitLab: проект → Settings → Repository → Protected branches → `main`. Allowed to merge: Maintainers. Allowed to push and merge: No one. Allowed to force push — выключено.

**2.4. Включить автоматический поиск ключей.**

- GitHub: репозиторий → Settings → Code security → Secret Protection и Push protection. После этого GitHub отклоняет отправку кода, в котором нашёл известный ему тип ключа.
- GitLab: попросите Claude добавить в `.gitlab-ci.yml` шаблон `Security/Secret-Detection.gitlab-ci.yml`.

Ключи Битрикса и Орбиты эти сервисы, скорее всего, не узнают. Поэтому проверка на шаге 4 обязательна в любом случае.

## Шаг 3. Дать доступ агенту

Агент получает отдельный ключ только к одному репозиторию, а не ваш личный доступ ко всему аккаунту. Тогда даже при ошибке он не тронет другие проекты, а ключ легко отозвать.

| Что нужно агенту | Что выдать |
| --- | --- |
| Только забирать и отправлять код | SSH-ключ репозитория (deploy key) |
| Ещё и открывать запросы на слияние (PR или MR) | Deploy key + токен на один репозиторий |
| Ваш личный SSH-ключ или токен со всеми правами | Не выдавать |

**3.1. SSH-ключ репозитория.**

1. Попросите Claude создать ключ и настроить его (промпт 2 в конце). Он покажет открытую часть — строку, которая начинается с `ssh-ed25519`. Её показывать можно, это не секрет.
2. Добавьте её в репозиторий:
   - GitHub: репозиторий → Settings → Deploy keys → Add deploy key → вставить строку, отметить Allow write access.
   - GitLab: проект → Settings → Repository → Deploy keys → Add new key → вставить строку, отметить Grant write permissions to this key.
3. Скажите Claude «добавил». Он проверит соединение.

**3.2. Токен для запросов на слияние** (если нужен).

- GitHub: аватар → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token:
  - Expiration — 30–90 дней;
  - Repository access — Only select repositories → нужный репозиторий;
  - Permissions → Contents: Read and write, Pull requests: Read and write. Больше ничего не включать.
- GitLab: проект → Settings → Access tokens → Add new token:
  - Role — Developer;
  - Scopes — `api`, `read_repository`, `write_repository`;
  - срок — 30–90 дней.

Токен показывают один раз. **Не вставляйте его в чат с Claude.** Вместо этого в терминале выполните `gh auth login` (GitHub) или `glab auth login --hostname <адрес GitLab>` (GitLab). Команда сама спросит токен, вставьте его туда. Токен сохранится в связке ключей macOS, и Claude сможет им пользоваться, не видя его.

**3.3. Ограничить права Claude Code на компьютере.** Попросите Claude создать файл `.claude/settings.json` с правилами (промпт 2):

| Действие | Правило |
| --- | --- |
| Смотреть состояние, историю, делать коммиты в своей ветке | без вопросов |
| Отправлять код на сервер, открывать PR/MR, менять адреса репозиториев | спрашивает вас |
| Перезаписывать историю, удалять репозиторий, читать `.env`, выводить токен | запрещено |

## Шаг 4. Работа и проверка перед выгрузкой

Агент работает в отдельной ветке закрытого репозитория, а в `main` изменения попадают только после вашего решения:

1. Claude создаёт ветку, делает изменения и прогоняет тесты.
2. Claude проверяет новые коммиты на ключи и личные данные.
3. Claude отправляет ветку и открывает запрос на слияние. Claude Code спросит ваше разрешение.
4. Вы смотрите запрос на GitHub или GitLab и нажимаете Merge.

**Перед первой публикацией проверяется вся история, а не только последние файлы.** Ключ, удалённый месяц назад, всё равно уйдёт вместе с историей. Для проверки дайте Claude промпт 3 и подставьте свои «опасные строки»: адрес тестового портала, свои телефоны, имена заказчиков.

В ответ Claude пришлёт отчёт. На что смотреть:

- **Вердикт** — «можно выгружать» или «нельзя».
- **Что найдено** — файл и коммит. Самих значений ключей в отчёте быть не должно.
- **Что станет публичным и требует вашего решения** — например, почты авторов коммитов.

Если в истории нашёлся настоящий ключ, не выгружайте репозиторий и переходите к разделу «Если секрет утёк».

Скриншоты и видео в репозитории просмотрите сами: ключ в поле ввода на картинке программы не находят.

## Шаг 5. Выгрузка и отзыв доступа

Выгружать можно только после вердикта «можно выгружать» на шаге 4. Вариант зависит от того, что именно вы публикуете.

**Вариант А. Открыть сам репозиторий.**

- GitHub: Settings → General → в самом низу Danger Zone → Change visibility → Make public.
- GitLab: Settings → General → Visibility, project features, permissions → Public.

**Вариант Б. Отдельная публичная копия** (как у робота первого контакта: закрытый GitLab и публичный GitHub). Напишите Claude «выгружай» (промпт 4). В публичную копию уходит только ветка `main`. Рабочие ветки туда не попадают.

После выгрузки откройте репозиторий в браузере в режиме инкогнито. Так вы увидите его глазами постороннего человека.

**Когда работа закончена, отзовите доступ агента:**

- [ ] GitHub: Settings → Developer settings → Fine-grained tokens → токен → Delete; репозиторий → Settings → Deploy keys → Delete
- [ ] GitLab: проект → Settings → Access tokens → Revoke; Settings → Repository → Deploy keys → Remove
- [ ] На компьютере: попросите Claude удалить ключ агента и выйти из `gh` или `glab`

## Если секрет утёк

Сначала перевыпустите ключ, и только потом чистите историю. Публичные репозитории боты просматривают за минуты, а GitHub ещё долго хранит старые коммиты. Одна чистка истории не спасёт.

1. **Перевыпустите ключ там, где он создан.**
   - Битрикс24: Разработчикам → Другое → Входящий вебхук → удалить старый и создать новый с теми же правами.
   - Орбита: кабинет → Разработчикам → отозвать ключ и выпустить новый.
   - Другие сервисы — в их настройках доступа.
2. **Поставьте новый ключ** в `.env` или в панель сервиса и проверьте, что всё работает.
3. **Посмотрите журналы** Битрикса и Орбиты: не было ли чужих действий со старым ключом.
4. **Попросите Claude вычистить ключ из истории** (промпт 5). Это единственный случай, когда историю переписывают. На это время придётся снять запрет force push с ветки `main` (шаг 2.3), а потом вернуть его.
5. **GitHub:** если репозиторий публичный, напишите в поддержку (support.github.com) с просьбой удалить закэшированные коммиты.
6. **Запишите в журнал проекта**, что утекло, когда и что перевыпущено.

## Готовые промпты

Промпты для Claude Code опираются на инструкцию для агента [docs/публикация/ДЛЯ-CLAUDE.md](ДЛЯ-CLAUDE.md). Там описаны точные команды и запреты, поэтому сами промпты короткие. То, что в угловых скобках, замените своим.

**Промпт 1. Подготовить проект (шаг 1)**

```text
Подготовь репозиторий <путь> к публикации по docs/публикация/ДЛЯ-CLAUDE.md, раздел «Подготовка».
Проверь .gitignore и .dockerignore, сделай .env.example, найди ключи в коде и в логах.
Рабочие заметки, ключи и видео из папки репозитория не удаляй — предложи, куда их перенести.
Ничего не коммить и не отправляй. В конце покажи список изменений.
```

**Промпт 2. Настроить доступ агента (шаг 3)**

```text
Настрой себе доступ к репозиторию <адрес репозитория> по docs/публикация/ДЛЯ-CLAUDE.md, раздел «Доступ»:
отдельный SSH-ключ для этого репозитория, запись в ~/.ssh/config, адрес remote и .claude/settings.json с правами.
Покажи мне открытую часть ключа и подожди, пока я добавлю её как deploy key. Потом проверь соединение.
Токены в чате не проси. Если нужен gh или glab — скажи, какую команду входа мне выполнить самому.
```

**Промпт 3. Проверить перед выгрузкой (шаг 4)**

```text
Проверь репозиторий <путь> перед выгрузкой в публичный <GitHub/GitLab> по docs/публикация/ДЛЯ-CLAUDE.md, раздел «Проверка».
Проверь всю историю всех веток.
Настоящие ключи лежат в <путь к .env> — сравни их с историей, но значения нигде не выводи.
Ищи также: <адрес тестового портала>, <свои телефоны>, <имена заказчиков>, <адрес закрытого репозитория>.
Ничего не исправляй и не отправляй. Отчёт: вердикт, что найдено (файл и коммит),
что станет публичным и требует моего решения, что предлагаешь исправить.
```

**Промпт 4. Выгрузить (шаг 5)**

```text
Выгружай. Перед отправкой проверь коммиты, которых ещё нет в <имя публичного remote>,
по разделу «Проверка» docs/публикация/ДЛЯ-CLAUDE.md. Если чисто — отправь только main в <имя remote>.
Если нашлось что-то — не отправляй, покажи отчёт.
```

**Промпт 5. Вычистить утёкший ключ (после того, как он перевыпущен)**

```text
Ключ <какой> уже перевыпущен. Вычисти старое значение из истории репозитория <путь>
по разделу «Утечка» docs/публикация/ДЛЯ-CLAUDE.md. Запрет force push на main я снял временно.
Сначала сделай резервную копию репозитория, покажи план и дождись моего «да».
```

## Чек-лист перед выгрузкой

- [ ] Ключи, заметки и видео лежат вне папки репозитория
- [ ] `.env`, базы, `data/` и логи есть в `.gitignore` и `.dockerignore`
- [ ] Репозиторий пока закрытый, ветка `main` защищена, поиск ключей включён
- [ ] Почта в коммитах скрыта или вы согласны её показать
- [ ] У агента отдельный ключ к одному репозиторию, а не ваш личный доступ
- [ ] Проверка всей истории (промпт 3): вердикт «можно выгружать»
- [ ] Скриншоты и видео в репозитории просмотрены глазами
- [ ] После выгрузки репозиторий открыт в инкогнито и просмотрен
- [ ] Доступ агента отозван, когда он больше не нужен
